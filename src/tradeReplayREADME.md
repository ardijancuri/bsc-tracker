# Integrated trade replay

`TradeReplayShare` captures the selected KOL/token activity when **Share trade** opens the dialog. It automatically prepares and exports the video; there is no separate generation button. The two-column dialog uses bscan's existing Manrope typography and colors, with the preview and replay controls on the left and image/video saving and sharing on the right. On mobile it becomes a single scrolling column.

The canvas drawing implementation and brand art are adapted from the user's newer `bscan-trade-replay-handoff (2)/bscan-trade-replay` folder. The supplied Downloads folder remains unchanged. The 1080 × 1350 card uses the supplied header, dotted chart, curved gold line, B/S circles, results panel, fingerprint pattern and gold brand footer. The UTC/pacing/gas footer line is removed.

`prepareTradeReplayData(activity, chart, position)` filters the exact wallet and token, sorts fills, preserves missing amounts, converts completed candle closes to interval-end timestamps and uses only explicitly reported supply. The replay ends at the final selected fill. `/api/kols/:address/tokens/:token/replay-chart` derives its historical window from confirmed database trades, preferring configured GMGN 30-second observations and then public GeckoTerminal one-minute observations from a verified token-containing pool. Provider work has a 20-second budget, coalesces identical windows, caches results and limits unique concurrent jobs. It rejects incomplete or discontinuous coverage. This route does not change the normal chart's available intervals.

`applyReplayMarketChart` accepts only finer history covering all selected trades. Missing or unavailable history retains the existing chart or labelled recorded-fill fallback. The supplied renderer builds a composite curve from market observations and recorded executions, uses its readable event pacing and trailing camera, and places B/S circles above each corresponding execution vertex. Preview, seeking and export share deterministic state. Execution prices remain separate from market samples in the underlying data.

Complete priced quantities must reconcile with a separately checked wallet balance no more than three minutes old before open-position values are shown. Missing, stale, transferred or incomplete flow is withheld. An explicitly labelled realized P&L can still use the backend's validated cumulative FIFO sale results when its indexed coverage and full realized summary are complete. Realized return uses recorded investment; it does not value open holdings or imply a verified closed position. No sample wallet, token or profit amount is embedded in production code.

The supplied indexed export is implemented with pinned Mediabunny 1.61.3. It encodes exactly 465 frames at 30fps over 15.5 seconds, at 8Mbps, preferring AVC MP4 and otherwise producing honestly labelled WebM when supported. Each frame has an explicit timestamp and duration. MediaRecorder is used only when WebCodecs is unavailable. Abort, encoder errors and timeouts dispose partial output. Each dialog session owns an offscreen canvas and guarded callbacks, so closing or React StrictMode cleanup cannot overwrite a reopened preview or exported file. Artwork loads through same-origin image handling; unavailable images use initials.

Save image and Copy image use the final PNG card. Save video downloads the exact prepared file. X opens an editable draft with the KOL link and caption; the saved MP4 must be attached manually because web intents cannot attach local files. Telegram shares the public KOL link. Supported devices also offer native file sharing from a fresh click. Nothing posts automatically, and cancelling native sharing preserves the prepared file.

Tests cover accounting, market-data acceptance and coverage, source pacing and geometry, indexed export and recorder cleanup, automatic-session cancellation and strict remounts, and exact-file sharing.
