# Integrated trade replay

`TradeReplayShare` captures the selected KOL/token activity and chart when its Share video button opens. The branded canvas is adapted from the user-supplied `bscan-trade-replay/public/replay-canvas.js` and its original SVG brand art. The source folder in Downloads is unchanged.

`prepareTradeReplayData(activity, chart, position)` filters the exact wallet and token, sorts fills, preserves missing amounts, converts completed candle closes to interval-end timestamps, and uses only explicitly reported supply. Candle history must continuously cover the selected trades, and the recap ends at the final recorded fill. Incomplete market coverage uses a visibly labelled recorded-fill line.

The market line, current quote, and B/S circles share one bounded interpolation of historical samples. Each circle uses its actual trade timestamp on the line; tooltips preserve recorded execution values, which can differ from the sampled market. A smoothly paced clock keeps trades readable without changing their horizontal time spacing. Equal-time trades share a horizontal position. The trailing camera uses revealed data, moves continuously, and holds the final trade frame. Seeking and export use the same deterministic state.

Rolling gross P&L is available only when complete priced quantities reconcile against a separately checked wallet balance no more than three minutes old. Missing, stale, transferred, or incomplete flow is withheld. A fill-only open replay cannot mark remaining inventory from historical fills. A reconciled closed replay can show cash proceeds minus investment. When gross P&L is unavailable, an explicitly labelled **realized P&L** can use the backend's validated cumulative FIFO sale results, provided indexed coverage and its full realized summary are complete. Realized return uses known recorded investment; it does not value open holdings or assert a checked current balance. The supplied sample's Tavern/SAFU amounts are not embedded in production code.

The same deterministic renderer drives preview and `captureStream(30)` recording at 1080 × 1350 for 15.5 seconds. `MediaRecorder` produces supported MP4 or explicitly labelled WebM. The generated file is offered through a separate download/share click to preserve a fresh user gesture. Cancelling, closing, unmounting, recorder failures, hidden tabs, and timeouts release capture tracks and frame scheduling. Same-origin image loading prevents a cross-origin logo or avatar from tainting export; unavailable artwork uses initials.

The JavaScript renderer retains the handoff drawing implementation; its TypeScript declaration defines the integration boundary. Data, motion, and recording lifecycle tests are in `tradeReplayData.test.ts`, `tradeReplayMotion.test.ts`, and `tradeReplayExport.test.ts`.

Download and X controls stay visible in a fixed footer while the preview scrolls. Generate once, then download the prepared file or open an editable X draft with the KOL page and a short caption. X web intents cannot attach the local file: the UI asks users to download and attach it themselves. Only MP4 enables the X action; WebM remains honestly labelled and downloadable. Supported devices also get a native Share file action, called directly from a fresh click and guarded against duplicate requests. Share cancellation preserves the file. No action posts automatically or authorizes an X account.
