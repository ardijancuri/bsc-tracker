# P&L evidence recovery, October 26

The public token position is complete only when its economic movements, costs,
fees, canonical balance and relevant decoding coverage are established. An
unrelated opaque transaction previously blocked every position in that wallet.
This release narrows that dependency only when authenticated creation evidence
proves the token did not yet exist, or a complete execution establishes the
actual contracts touched. Same-block ambiguity remains blocking.

Creation certificates preserve the true transaction, block, protocol and exact
constructor/runtime authentication. They are compact fields in existing launch
facts, not new periodic histories. A bounded worker certifies creation for
recently traded/selected tokens. Unknown-token trading contexts receive early
complete execution capture without waiting for token admission or accounting.
The existing private node tracing interface remains private.

Historical repair uses checksummed original receipts and genuine dated traces
or pool observations. The finite operator validates canonical node headers and
complete transaction/receipt identities before its transaction. It appends
proofs and schedules ordinary decoding; it does not write invented financial
amounts or overwrite original receipts, errors, first failures or expiry.
Historical discovery distinguishes existing-at-boundary contracts from genuine
new deployments. Pool creation alone does not establish token birth.

Registered stock quote settlement uses the approved actual acquisition-cost
allocation: exact native expense is split between tokens consumed and returned
quote change. Transaction gas remains separate. Intermediate token decimals
cancel only in authenticated raw-unit ratios. Historical quote conversion uses
dated pool evidence and a dated BNB/USD observation; a current quote or stablecoin
peg never supplies a missing historical value.

Cost-only corrections rebuild affected FIFO results while retaining a previously
matched balance proof only when quantities, immutable movement identities,
membership and canonical observation context still agree. New movements,
quantity changes, reorgs and membership changes follow ordinary invalidation.
The original proof time/block is retained, never refreshed by the correction.

Two pinned older ERC20 deployments have an audited method that emits synthetic
Transfer-shaped logs without moving holdings. Their original creation/runtime
and that exact method are authenticated independently. Recognizing this method
does not classify the entire token as nonfinancial, admit its old trading history,
or exclude genuine ERC20 transfers.

Their two exact canonical creation headers are retained as a bounded exception
to header expiry. Older sparse GANG history invalidated an earlier assumption
that the globally oldest retained header described continuous coverage. Bootstrap
now stores and validates these two real headers before approving its reader.
All other ordinary temporary evidence keeps the existing retention policy.

Authenticated token admission also schedules a bounded scan of the retained
receipt buffer. A previous release could finish an unknown token receipt with
zero financial facts, leaving later sells without their real earlier purchases.
The new leased job requeues only original watched-wallet token movements missing
from the ledger. It keeps its keyset cursor in the existing jobs table, processes
at most 64 rows / 2 MiB compressed / 16 MiB decoded per page and yields to capture.
Additive provenance records the original completion status; raw identities,
expiry, first failures and existing delivery evidence are retained.

Pending normalization races are invalidated by the receipt's payload CAS.
Membership, canonical birth/target context and leases are rechecked; reorgs revoke
affected jobs. Completed scan jobs retire after their bounded retention period.
Previously completed historical receipts cannot send new historical alerts, while
genuine pending first-trade captures retain normal live delivery behavior.

These changes do not restart the canceled eight-hour validation. They add no
financial-response snapshots, permanent market-swap history or new domain tables.
P&L continues to use compact financial facts, FIFO allocations, current positions
and stored rolling KOL totals. Unknown original acquisition costs remain unknown.

Local evidence and operator manifests are private under
`.cache/fresh/private/pnl-gaps-20261026/`. The task uses a separate production
clone; existing databases, accounts, settings and the Fresh boundary are retained.

## Shared recovery and market support

Repairs are grouped by missing evidence or protocol, not by KOL identity. A
canonical execution is captured once, normalized through the same decoder, then
applied to every affected accounting book. Archive recovery appends authenticated
original state or complete execution traces to the existing repair buffer;
ordinary decoding owns the financial changes. Operator bundles cannot set a
KOL's P&L or approve a guessed amount.

The shared market paths support authenticated historical V2 conversions,
registered V4 marks and the supported native, hook-free Pancake Infinity CL key
variant. Current prices read confirmed pool state. Historical marks use dated
state or genuine settled swaps with a complete bounded liquidity-event window.
An initialization price, absent liquidity, current state or an unsupported hook
cannot substitute for missing historical evidence. Unsupported Infinity keys
retain explicit diagnostics without stopping discovery of a later supported key.

Original purchase lots and recorded movements still determine FIFO cost. A
completed repair rebuilds only the affected books and updates their stored
rolling 24-hour totals. Profiles and leaderboard read those same totals; normal
page loads do not rescan history. Incomplete accounting cannot be ranked as a
complete realized P&L, and optional chart or artwork failures cannot invalidate a
verified realized total.

Public token launch eligibility can use the explicitly configured discovery
archive after the VPS node no longer serves old contract state. This worker-only
adapter sends contract code, headers and allowed birth evidence, with one active
request, 20 requests per minute and a one-second minimum interval. It cannot
request wallet history, prices, financial accounting or chain writes. Each wire
requires a retained, checksummed, canonical positive token Transfer involving a
currently monitored public KOL; private-only, expired, corrupt, revoked and
orphaned observations never enable the external adapter. A verified pre-boundary
code observation is cached once per token in the existing discovery job and
serves every affected wallet. Provider failure leaves eligibility pending and
cannot approve an unknown launch or interrupt a valid recent node-only proof.

Infinity historical marks retain bounded canonical header observations inside
the existing receipt proof when sparse collection did not retain another
trader's swap block. These are genuine node observations tied to the same target
and authentic pool events. They do not advance collection checkpoints or create
a permanent market-event table. Known conflicting database hashes reject the
proof; replay of the retained proof requires no historical network calls.

KOL profile token pages materialize the eligible traded-token IDs for the
requested public wallet once, before sorting and pagination. This preserves the
same public role, scope, monitoring interval, capture, launch-admission, exclusion
and GANG exception rules while avoiding a repeated global trade-existence query
for every token. The initial six cards still share one bounded summary batch.
This adds no cache, index, history table or request-time financial recalculation.

## October 27: recurring discovery and false-transfer recovery

Historical token-birth searches now retain bounded, deduplicated code and header
observations in their existing jobs. Each resumed observation is checked against
the canonical node header; final admission still verifies the exact adjacent
code states and canonical creation evidence. An interrupted search continues its
work instead of restarting after every provider cooldown. The stable first
observation anchors the search, and fresh node evidence is attempted before the
optional archive. Successful publication removes the temporary search payload.

Two independently audited stateless emitter code families are recognized from
their complete canonical creations. Only the verified immutable metadata words,
or the two literal getter strings and fixed CBOR hash data, may vary. Executable
code, dispatch, constructor returns and immutable patches remain authenticated;
literal control-flow analysis rejects any possible jump outside executable code.
This does not classify arbitrary contracts from their name, symbol, deployer or
failed balance call. Storage-backed and delegating token implementations do not
match these families.

Existing false interpretations are corrected with a finite, reviewed operator:
original financial IDs and all quantities, values and fees remain unchanged;
only the proven false events lose canonical accounting status. Original receipt
bodies, TTLs, diagnostics and delivery evidence remain retained. Only affected
public books are rebuilt, and genuine positions and matched balance observations
must remain exact. No partial realized subtotal becomes a ranked complete P&L.

The public archive guard also accepts a canonical, successful direct zero-native
`approve(address,uint256)` from an original captured public wallet when its exact
ABI calldata and matching owner/spender/amount Approval event agree. This permits
contract-age verification for fee-only approvals, which the decoder already
tracks, without inventing a transfer. Removed, private, expired, orphaned,
router-only and malformed contexts remain denied. This permission is only for
bounded contract-birth lookup; financial eligibility and accounting remain
independently verified.

## October 28: prevent recurring pending totals

Discovery can verify the initialized Fresh boundary after the node prunes that
header. This exception is restricted to the stored starting block number, hash
and timestamp, with exact archive header bookends. An owned-node contradiction
still rejects, and other missing historical headers gain no exception. Recent
mint searches start with a short bounded window; unavailable older ranges cannot
hide a genuine recent candidate. Mint logs still require an authenticated birth
certificate. New discovery jobs get prompt service without starving overdue
retries. Sanitized original provider failures survive subsequent cooldowns.

Urgent collection records a small, authenticated original-block V2 quote/native
reserve proof while node state is available. Its official factory, deterministic
pair, assets, code hashes and positive reserves are checked at the same block.
Later transfer marks reuse that proof without historical RPC. The proof is
explicitly block-end state and cannot replace a before-execution settlement
price. Existing request, concurrency, deadline, receipt-size and privacy limits
remain in force.

Native sale normalization distinguishes actual wallet proceeds from gross
router output and separately signed upfront expenses. A narrowly authenticated
single EntryPoint operation can also prove its native sale payout. These paths
require complete original execution traces and closed wallet cash/token flows;
transaction or operation gas is still charged once.

When unresolved raw evidence reaches its agreed 72-hour expiry, its existing job
retains a compact unavailable reference containing original transaction/block,
wallets, dependency identity, checksum and diagnostics. Raw bodies still expire;
financial records do not. This reference neither clears a coverage gap nor
approves unknown P&L, but preserves the exact identity needed for later recovery.

High-traffic discovery keeps new `lastSeen` and wallet membership observations
without restarting a valid earlier birth search. Concurrent changes must be
monotonic and independently revalidated against original retained receipts and
current monitoring membership. Changes to the original context, search proof,
lease, boundary or canonicality still abort publication.

An authenticated native purchase can allocate actual acquired quote cost between
the purchased token and genuinely returned intermediate change. This follows the
same approved acquisition-cost policy used for stock quotes, but a non-stock
quote requires its own complete signed execution and closed acquisition/payment/
return proof. Original raw quantities cancel in the cost ratio; neither a peg,
default decimals nor a guessed dust price is used. The compact financial record
retains its execution binding and exact rational allocation.

The worker reserves every fourth decoding pass for already-due repair receipts.
Continuous new arrivals cannot permanently starve a recovered purchase cost;
future-due backoffs, block grouping and financial validators remain unchanged.
Nested acquisition-proof objects are compared canonically across PostgreSQL JSONB
round trips while preserving every value and array order. A real value or proof
identity change still fails the existing conflict gate.

A copied-name stateless emitter family is authenticated from its complete
constructor and fixed executable body. Only bounded literal name/symbol and
unreachable compiler-metadata data may vary. Closed-jump analysis and a complete
stateless opcode check remain mandatory; token names do not establish exclusion.
Reviewed corrections retain false original interpretations as noncanonical rows
and preserve every genuine financial field and current position.
